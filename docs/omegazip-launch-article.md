# Свой архиватор с форматом .oz: дедуп, бэкапы и честное сравнение с 7-Zip

Привет всем. Меня зовут Ренат. Последние полтора года в свободное от основной работы время я делал архиватор. Не очередной GUI поверх 7z, а инструмент со своим форматом контейнера, своим конвейером сжатия и, честно признаться, кучей граблей. Сегодня выношу **OmegaZip** на суд публики: расскажу, зачем он нужен, как устроен внутри, и покажу цифры — в том числе те, где мой формат проигрывает 7-Zip.

## Предыстория: зачем ещё один архиватор

У меня накопились десятки версий проектов, папок с исходниками, бэкапов. И каждый раз одна и та же боль: **ZIP хранит дубликаты по отдельности**. Сжал папку с тремя копиями почти одинакового конфига — и получил трижды упакованный мусор. Хотелось дедупликации, как в Borg или restic, но чтобы архив можно было открыть двойным кликом, без отдельного «клиента бэкапов».

Посмотрел на существующее:
- **7-Zip** — великолепный, но без дедупа *между файлами внутри контейнера* и без удобного бэкап-репозитория;
- **Borg / restic** — супер для бэкапов, но это не «открой архив»;
- **WinRAR** — платно и без интересных мне фич.

Решил скрестить: простой архиватор с дедупом, solid-потоками и репозиторием бэкапов. Получилось то, что получилось.

## Архитектура

Ядро — на Rust, GUI — на Tauri (десктоп), плюс CLI и сборка под Android. Конвейер сжатия — 4 модуля:

1. **Семантический анализ** — тип по содержимому: magic-байты, энтропия, доля текста.
2. **Препроцессор** — опциональная подготовка (например, lossy PNG/JPEG через внешние утилиты, если доступны).
3. **Выбор кодека** — по контексту берётся предпочтительный, затем в пари памяти сравниваются несколько вариантов и берётся лучший по размеру. Кодеки: Dense (энтропийный), Balanced, Fast, MaxRatio, Store.
4. **Глобальный дедуп** — блоки по хешу хранятся в одном экземпляре.

### Формат .oz (v2)

Упрощённо, на диске контейнер выглядит так:

```
OMEGAZIP\x02
flags:  bit0 = chunked, bit1 = encrypted, bit2 = solid
[если encrypted] salt 16 байт
manifest (JSON):
    список файлов
    при chunked  -> chunks: [{hash_hex, algo, len}]
    при solid    -> solid: {stream_id, offset, length}
блоки:
    32 байта hash + 1 байт codec + 4 байта len + data
[если encrypted] nonce 12 + ciphertext+tag (ChaCha20-Poly1305)
```

Ключ из пароля выводится через **Argon2**, каждый блок шифруется **ChaCha20-Poly1305** независимо — без пароля данные недоступны.

Ключевые фичи формата:
- **Chunked dedup** — файлы режутся на чанки 64 КиБ; одинаковые блоки хранятся один раз (как в Borg/restic). Выигрыш на VM-образах, видео с повторами, версиях проектов.
- **Solid** — все файлы в один сжатый поток (как в 7-Zip), лучше сжимает похожие файлы рядом.
- **Шифрование** — Argon2 → ключ, ChaCha20-Poly1305 на блок.
- **Recovery** — блоки восстановления Reed–Solomon поверх полосы, на случай частичной порчи носителя.
- **Пресеты** — `fast | balanced | max | ultra` (ультра = XZ-9 + recovery) и `auto` по типу файла.

Командная строка выглядит привычно:

```bash
# Сильное сжатие с дедупом, solid и шифрованием
omegazip compress --preset ultra --chunked --solid --recovery \
  --password "секрет" ./data archive.oz

# Экспорт обратно в обычный ZIP (откроется где угодно)
omegazip export-zip archive.oz archive.zip

# Репозиторий бэкапов
omegazip repo init   ./myrepo
omegazip repo backup ./myrepo ./data
omegazip repo restore ./myrepo 1 ./restored
```

## Чем это отличается от 7-Zip — честно

Самое важное: **.oz — это не LZMA2**. Это другой контейнер, заточенный под дедуп и повторяющиеся данные. Я не утверждаю паритета по алгоритму.

- Для **максимального сжатия одиночного большого файла** 7-Zip с LZMA2 — эталон, и .oz его на одном файле не догонит.
- Мой выигрыш — там, где много **похожих и повторяющихся** данных: версии проектов, бэкапы папок, наборы похожих файлов.

Если вы откроете одиночный уже сжатый JPEG — никто его сильно не сожмёт, ни я, ни 7-Zip. Об этом прямо написано на сайте.

## Цифры

Это зафиксированные прогоны из репозитория (не «в лучшем случае»):

| Корпус | Вход | ZIP | .oz | Разница |
|--------|------|-----|-----|---------|
| Versioned (3083 файла) | 99.17 МБ | 58.31 МБ | 52.72 МБ | **−9.6%** |
| Смешанный (6756 файлов) | 40.25 МБ | 33.89 МБ | 32.22 МБ | **−4.9%** |

KPI `oz_vs_zip_size_pct`: 63.1% (цель ≥ 10%) — PASS. KPI `time_regression_pct`: 104.3% (цель ≤ 150%) — PASS, то есть .oz упаковывает почти в те же сроки, что и ZIP, но компактнее.

## Бэкапы как в Borg

Отдельная фича, ради которой, собственно, всё и затевалось, — **репозиторий бэкапов**:

```bash
omegazip repo backup ./myrepo ./data   # снимок
omegazip repo list   ./myrepo          # список снимков
omegazip repo push   ./myrepo /mirror  # копия репо локально
omegazip repo rclone-sync ./myrepo remote:bucket/prefix  # в S3/SFTP через rclone
```

Дедуп работает *между снимками*, поэтому ежедневный инкрементальный бэкап почти ничего не весит. Облако подключается через `rclone` (S3, SFTP) — нативного SDK в формате .oz нет, синхронизируется папка репо.

## Интеграция в ОС

Хотел, чтобы не приходилось открывать программу ради упаковки папки:
- **Windows** — контекстное меню проводника «Сжать в .oz / .zip», ассоциация `.oz`, тихая распаковка без главного окна.
- **macOS** — сервисы Finder, сжатие из меню.
- Ассоциация файлов: двойной клик по `.oz` открывает и распаковывает рядом.

Форматы: нативно открываются `.oz`, ZIP, tar (.gz/.xz/.bz2/.zst), CAB; с установленным 7-Zip/p7zip — 7z, RAR, ISO, WIM, MSI.

## Честные ограничения

Не буду рисовать идеальную картинку:
- **Intel Mac** пока в планах — сейчас только Apple Silicon (M1/M2/M3).
- **Создание RAR** не поддерживается — формат проприетарный; распаковка RAR есть (через 7-Zip).
- **Установщик пока без EV-подписи** → Windows покажет SmartScreen («неизвестный издатель»). Скачивайте только с `omegazip.ru` и проверяйте SHA-256 на странице загрузки. Подпись кода — вопрос бюджета, не техники.
- **7z/RAR/ISO** открываются только при установленном 7-Zip (Windows) или p7zip (Linux); на macOS интеграция пока не «из коробки».

## Монетизация

OmegaZip **бесплатен и без подписок**. Развиваю на добровольных донатах — по желанию, без навязывания.

Реалистично понимаю: архиватор — это коммодити, 7-Zip бесплатен и «вечен». Поэтому ставлю на **open-core** как будущий путь к деньгам: облачные бэкапы «из коробки», командная лицензия, приоритетная поддержка. Но ядро останется бесплатным — это моё принципиальное решение.
