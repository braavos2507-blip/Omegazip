# Почему не работало и что сделано

## 1. Диалоги выбора файла/папки (macOS)

**Причина:** У tauri-plugin-dialog на macOS известные проблемы: диалог с `directory: true` может не возвращать путь или падать; callback-версия диалогов не всегда вызывается с главного потока, из-за чего наш код с `run_on_main_thread` + `sync_channel` мог не получать ответ.

**Что сделано:** На macOS все диалоги (файл/папка, сохранить, архив .oz) переведены на **rfd** (Rust File Dialog). rfd вызывает нативные NSOpenPanel/NSSavePanel и стабильно работает. Команды `pick_file_or_folder`, `pick_save_file`, `pick_folder`, `pick_oz_file` на macOS теперь используют rfd в `run_on_main_thread`.

## 2. Drag-and-drop

**Причина:** В Tauri окно — это webview. На macOS дроп часто обрабатывается webview’ом, а не нативным окном; в HTML-дропе путь к файлу в webview может быть недоступен. События `drop-files` и `tauri://drop` приходят только если дроп попадает в нативное окно.

**Что сделано:** В UI добавлена подписка на `getCurrentWindow().onDragDropEvent()` — это даёт пути при дропе, когда Tauri их передаёт. Если дроп по-прежнему не срабатывает, это ограничение связки webview/macOS в Tauri.

## 3. Сервисы Finder («Сжать в OmegaZip»)

**Причина:** Пункты в меню «Сервисы» появляются из-за NSServices в Info.plist, но **обработчик** сервиса — это метод Objective-C (например `openFiles:userData:error:`), который система вызывает с **приватным** pasteboard. Tauri не реализует такой обработчик. Наш обход (чтение общего буфера при `Resumed`) не помогает: при вызове сервиса данные лежат в приватном pasteboard сервиса, а не в общем.

**Что сделано:** Регистрация настоящего NSServices-provider’а на Rust (objc2 `define_class!`) упирается в ограничения трейтов (Message/Encode для кастомного класса). Пока оставлен обход через pasteboard при Resumed (может сработать только в редких сценариях). Для полной поддержки сервисов нужен отдельный маленький модуль на Objective-C/Swift, который примет вызов сервиса и передаст пути в приложение (например через событие или сокет).

## Итог

- **Диалоги:** на macOS должны работать через rfd (пересобери и проверь кнопки «Файл или папка», «Куда сохранить», «Папка назначения», «Архив .oz»).
- **Дроп:** улучшен за счёт `onDragDropEvent`; если не работает — ограничение платформы.
- **Сервисы:** без нативного Obj-C/Swift обработчика пункты меню по сути пустые; пока надёжный способ — кнопки в приложении или дроп.

Пересборка: `npm run build:macos` (или без CI: `unset CI && npx tauri build`). Контекстное меню в Finder — `./scripts/install-context-menu.sh`. Опциональный инжект `NSServices` в `.app`: `npm run build:macos:with-nsservices` (не смешивать с workflows, иначе дубликаты в «Сервисы»).
