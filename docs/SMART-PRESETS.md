# Умные пресеты (.oz)

Требования **SMART-01** / **SMART-02**: подбор профиля **`Preset`** (fast / balanced / max / ultra) по **расширениям** входа, без потерь и без лишнего CPU на уже сжатых данных.

## Где реализовано

- **Логика:** `src/smart_preset.rs` — `suggested_preset_for_path`, `suggest_compress_preset_hint`.
- **GUI:** пункт «**Авто (по типу файлов)**» в селекторе профиля `.oz`; команда Tauri `suggest_compress_preset`.
- **CLI:** `omegazip compress ... --preset auto` (после разбора пути к источнику).
- **Внутри блоков .oz:** классификация `DataContext` и кодек **Store** для медиа — см. `src/analyzer.rs`, `src/codec.rs` (дополнительный уровень, не заменяет пресет целиком).

## Эвристики (кратко)

| Итоговый `Preset` | Когда |
|-------------------|--------|
| **fast** | Уже сжатые типы: видео/аудио (`.mp4`, `.mp3`, …), lossy-растры (`.jpg`, `.webp`, …), архивы/потоки (`.zip`, `.gz`, …), образы дисков и т.п. **PDF / EPUB / книжные** при упаковке в **`.oz`** идут в **balanced** (чанки), чтобы не терять эффективность. Для **папки** — если в выборке до 400 файлов **нет** ни одного «текст/код/lossless-изображение» и все известные расширения из группы «уже сжато». |
| **balanced** | Исходный код и текст (`.rs`, `.py`, `.md`, …), **lossless**-изображения (`.png`, `.tiff`, …), неизвестные расширения, **смешанные** папки, пустая папка. |

**max** / **ultra** через авто **не выбираются** — только явный выбор пользователя.

## SMART-02 (без потерь)

Формат **.oz** остаётся **обратимым**. Авто-пресет влияет на **чанки / solid / recovery**, а не на введение lossy-кодирования. Для медиа внутри архива по-прежнему может выбираться **Store** на уровне блока.

## Лимиты обхода папки

- До **`DIRECTORY_SAMPLE_CAP`** (400) файлов, глубина до **`DIRECTORY_MAX_DEPTH`** (32) — см. константы в `smart_preset.rs`.
