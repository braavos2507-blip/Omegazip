# OmegaZip и «топ-5» архиваторов (GAP-03)

В требованиях v1.1 ориентиром названы возможности продуктов уровня **7-Zip, WinRAR, WinZip, Bandizip, PeaZip**. Этот документ — **честное** сопоставление: где OmegaZip даёт сопоставимый опыт, где нужен **7-Zip / p7zip**, а где расхождение **намеренное** (non-goals).

Подробная матрица форматов по чтению/записи: [FORMATS.md](FORMATS.md).

## Легенда

| Статус | Значение |
|--------|----------|
| **Pass** | Для типичного сценария класса задач поведение сопоставимо с ожиданием от «классического» архиватора (с учётом модели OmegaZip: нативное ядро + опциональный 7-Zip). |
| **Partial** | Возможно только при условиях (установлен 7-Zip, платформа, обходной путь) или с документированными ограничениями. |
| **N/A** | Вне scope продукта или не применимо к заявленной модели. |

## Классы форматов и сценариев

| Класс | OmegaZip | Типичное ожидание «топ-5» | Статус | Комментарий |
|-------|----------|---------------------------|--------|--------------|
| Собственный продвинутый контейнер (аналог «наш .7z / solid / дедуп») | **`.oz`** — нативно, чанки, solid, шифрование, recovery | У каждого продукта свой «лучший» формат | **Pass** | Конкурирует по смыслу с «родным максимальным» режимом; не копирует бит-в-бит .7z. |
| ZIP и OOXML-подобные | Нативно чтение/запись (обычный ZIP) | «Полная» поддержка ZIP у конкурентов часто включает шифрование | **Partial** | Обычный ZIP без шифрования — **Pass** по смыслу; **ZIP с шифрованием** в нативном пути OmegaZip — нет (см. [FORMATS.md](FORMATS.md)); через 7-Zip — по возможностям 7-Zip. |
| tar.\* (gzip/xz/bz2/zst) | Нативно список/распаковка; запись **tar.gz** нативно | Расширенная работа с tar | **Partial** | Создание не-tar.gz tar-вариантов как цели `compress` — см. матрицу в [FORMATS.md](FORMATS.md). |
| Одиночные `.gz` / `.xz` / `.bz2` / `.zst` | Нативно чтение | Сжать/распаковать поток | **Partial** | «Сохранить как архив» обычно уводит в `.oz` / `.zip` / `.7z` / `.tar.gz`, не в «голый» `.zst`-контейнер как единственный выход. |
| **7z** | Через 7-Zip | Полная поддержка | **Partial** | Паритет с экосистемой **вашего** установленного 7-Zip, не встроенный кодек в бинарнике OmegaZip. |
| **RAR** | Распаковка через 7-Zip; **запись RAR — нет** | Чтение/запись у WinRAR | **Partial** / **N/A** | Чтение — **Partial** (нужен 7-Zip). Запись RAR — **N/A** (проприетарный формат; см. [REQUIREMENTS.md](../.planning/REQUIREMENTS.md) Out of Scope). |
| ISO, WIM, MSI, DMG, пакеты `.deb`/`.rpm` и др. | Через 7-Zip при наличии | Открывается архиватором | **Partial** | То же: делегирование 7-Zip; без него — недоступно. |
| CAB | Нативно чтение; запись — нет в матрице compress | Редко нужна запись CAB | **Partial** | Запись CAB — не цель v1.x (см. [FORMATS.md](FORMATS.md)). |
| Широкий зоопарк «всё, что открывает 7-Zip» | Делегирование `7z` при успешном тесте/расширении | «Открылось — значит поддерживается» | **Partial** | OmegaZip **намеренно** не встраивает все кодеки; паритет формулируется как: *если ваш 7-Zip открывает файл, OmegaZip может делегировать* ([FORMATS.md](FORMATS.md), раздел про `7z t`). |

## Платформы

| Аспект | OmegaZip | Комментарий |
|--------|----------|-------------|
| Windows / macOS / Linux (десктоп) | GUI Tauri + CLI | **Pass** для заявленных целей; интеграция ОС — [CONTEXT-MENU.md](CONTEXT-MENU.md), [FILE-ASSOCIATIONS.md](FILE-ASSOCIATIONS.md). |
| Android | Отдельное приложение, **без** внешнего 7-Zip | **Partial** относительно десктопного «топ-5»: нативные форматы только; см. [FORMATS.md](FORMATS.md) и [ANDROID_BUILD.md](../ANDROID_BUILD.md). |

## Намеренный non-parity (не баг)

1. **Нет встроенного клона всех кодеков WinRAR/WinZip/Bandizip** — один бинарник OmegaZip + опциональный **внешний** 7-Zip для «не-нативных» контейнеров.
2. **Создание RAR** — вне scope (лицензирование и политика проекта).
3. **Полный паритет по каждому нишевому формату без 7-Zip** — не цель; см. колонку **Partial** и [INSTALL.md](INSTALL.md).

## Итог для GAP-03 (FMT-01b)

**«Полный паритет с топ-5 по охвату форматов»** в дословном смысле **не заявляется**: OmegaZip даёт **сопоставимую практику** за счёт нативного ядра + **того же класса** делегирования, что и у экосистемы 7-Zip, с явными **Partial** и **N/A** выше.

## Измерения

Чтобы подкрепить заявления о `.oz` цифрами на своих данных: [MEASURABLE-QUALITY.md](MEASURABLE-QUALITY.md), скрипт `scripts/measure-oz-advantage.sh`.

**Зафиксировано (автопрогон, 2026-04-10):** на синтетическом корпусе из **100 идентичных** файлов chunked `.oz` (**balanced**) дал архив **~73% меньше**, чем нативный ZIP того же CLI (`zip_bytes=64022`, `oz_bytes=17245`). На малом проекте без массовых дубликатов (`hellogitworld-master`) ZIP оказался меньше.

На реальном интернет-корпусе из нескольких версий open-source проектов (jQuery + Bootstrap, ~3083 файлов) chunked `.oz` дал архив **~18.1% меньше ZIP** (`zip_bytes=61238454`, `oz_bytes=50177021`) — см. `CORPUS_EXTRA=/Users/renat/01Project/OmegaZip/Архивы` в прогоне `npm run measure:oz-repo-corpora`.
