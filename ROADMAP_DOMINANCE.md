# OmegaZip — план доминирования во всех сценариях (2026+)

Цель: сделать OmegaZip **лучшим выбором** в каждой строке сравнения: макс. сжатие, бэкапы, шифрование, совместимость, GUI, восстановление.

---

## Фаза 1: Догнать и перегнать по «чистому» сжатию (vs 7-Zip / ZPAQ)

### 1.1 Максимальное сжатие
- [x] **XZ-9 в конвейер** — `max_ratio_ultra_encode` (XZ level 9) для режима Ultra.
- [x] **Профиль "ultra"** — пресет: solid + XZ-9, recovery 2. CLI: `--preset ultra`, GUI: пресет «Ultra».
- [ ] **Размер словаря / solid-блока** — в solid-режиме опционально разбивать на блоки по N MiB (как 7-Zip solid block size) для компромисса память/соотношение.

**Результат:** В сценарии «максимальный размер архива один раз» OmegaZip не уступает 7-Zip ultra (solid + LZMA2/XZ-9).

---

## Фаза 2: Репозиторий и инкрементальные бэкапы (vs Borg / Restic / Kopia)

### 2.1 Репозиторий чанков
- [x] **Формат репозитория** — директория с `chunks/ab/cd/hashhex`, `snapshots/snapshot_N.json`.
- [x] **Команды:** `omegazip repo init <path>`, `omegazip repo backup <repo> <source>`, `omegazip repo restore <repo> <id> [dest]`, `omegazip repo list <repo>`.

### 2.2 Инкрементальность
- [x] **Бэкап с дедупом** — при backup чанки по хешу не дублируются; манифест снапшота ссылается на чанки (новые + существующие).
- [x] **Дедуп между снапшотами** — общий chunk store; несколько снапшотов разделяют одни и те же чанки (как Borg).

### 2.3 Политики и удалённое хранилище (опционально)
- [ ] **Retention** — сохранять последние N снапшотов или по расписанию (daily/weekly/monthly).
- [ ] **Бэкенд** — абстракция «хранилище»: локальная папка, затем (при желании) SFTP, S3-совместимый API. Первая итерация — только локальный репозиторий.

**Результат:** В сценарии «бэкап на сервер / много версий» OmegaZip конкурирует с Borg/Restic/Kopia: репозиторий + инкремент + дедуп между снапшотами.

## Фаза 3: Восстановление и надёжность (vs WinRAR)

### 3.1 Recovery records в формате .oz
- [x] **Секция recovery в v2** — после блоков: num_stripes; для каждой полосы (16 блоков): max_len, 2 parity (Reed-Solomon). При чтении: при неверном CRC восстанавливать из полосы.
- [x] **Включение в CLI/GUI** — флаг `--recovery` (2 parity на полосу), запись recovery при сжатии; при распаковке автоматическое восстановление повреждённых блоков.
- [x] **CRC32** — на каждый блок при recovery: хранить CRC32; при чтении проверять и при несовпадении использовать recovery.

**Результат:** Как WinRAR: «архив на 10+ лет» и «повреждённый носитель» — восстановление без потери данных в пределах parity.

## Фаза 4: Кроссплатформа и UX (vs все)

### 4.1 Windows и Linux
- [ ] **Сборка Tauri под Windows и Linux** — проверить/исправить сборку (npm run tauri build на каждой ОС или CI), упаковка: installer (Windows), .AppImage / .deb (Linux).
- [ ] **Ассоциация файлов** — .oz открывается в OmegaZip на Windows/Linux (как в macOS).

### 4.2 GUI
- [x] **Прогресс при распаковке** — событие `decompress-progress`, прогресс-бар в GUI.
- [x] **Просмотр архива без распаковки** — кнопка «Список файлов», `list_archive`, вывод в alert.
- [x] **Пресеты в GUI** — выпадающий список: Быстро, Сбалансировано, Максимум, Ultra; чекбоксы Чанки, Solid, Recovery.

### 4.3 CLI
- [x] **Пресеты** — `--preset fast|balanced|max|ultra`.
- [x] **Информация об архиве** — `omegazip info archive.oz`, `omegazip list archive.oz`.

**Результат:** Один архиватор на всех ОС с понятным GUI и CLI под все сценарии.

## Фаза 5: «Убийца комбо» — финальные штрихи

### 5.1 Совместимость и доверие
- [ ] **Открытая спецификация .oz** — документ (или отдельный репозиторий) с полным форматом v1/v2 (байт в байт) для парсеров и восстановления.
- [ ] **Режим «только ZIP»** — опция «Сохранить как ZIP» при сжатии: тот же конвейер (анализ, дедуп не между файлами в ZIP, но можно store/deflate), на выходе только .zip (макс. совместимость без .oz).

### 5.2 Производительность
- [x] **Параллельное сжатие файлов** — rayon: подготовка файлов параллельно, затем запись в store и на диск.
- [ ] **Потоковая запись** — не держать весь архив в памяти: писать блоки на диск по мере формирования (уже частично так).

### 5.3 Безопасность
- [x] **Пароль из окружения/файла** — `OMEGAZIP_PASSWORD`, `--password-file` для compress/decompress/export-zip.
- [ ] **Стирание ключа из памяти** — zeroize (зависимость добавлена), подключить где возможно.

**Результат:** Максимальное доверие (спецификация, безопасность пароля) и скорость (параллелизм, потоковая запись).

## Краткий чеклист «выиграть всех»

- [ ] **7-Zip:** solid + LZMA2/XZ-9 (ultra), пресет `max`/`ultra` → не уступаем по размеру.
- [ ] **Borg/Restic:** репозиторий + инкремент + дедуп между снапшотами → конкурируем в бэкапах.
- [ ] **WinRAR:** recovery records включены, CRC + восстановление при чтении → не уступаем по надёжности.
- [ ] **ZIP/совместимость:** экспорт в ZIP уже есть; опция «сразу в ZIP» — по желанию.
- [ ] **Все платформы:** Tauri Windows/Linux + пресеты + прогресс везде → один инструмент на всё.

После выполнения фаз 1–4 OmegaZip по функционалу покрывает все сценарии таблицы и претендует на место «лучшего универсального архиватора» 2026+.
