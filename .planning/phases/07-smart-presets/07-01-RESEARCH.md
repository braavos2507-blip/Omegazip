# Phase 7 — RESEARCH: умные пресеты

**Требования:** SMART-01, SMART-02  
**Цель дорожной карты:** по умолчанию выбирать режим сжатия по типу контента с балансом скорости/размера; **без потерь** для lossless-типов; для уже сжатых данных — не тратить CPU впустую.

## Что уже есть в ядре

| Механизм | Где | Роль |
|----------|-----|------|
| **Пресеты .oz** | `src/pipeline.rs` — `Preset`, `apply_preset` | `fast` / `balanced` / `max` / `ultra` задают chunked, solid, recovery. |
| **GUI / CLI** | `ui/index.html`, `compress_advanced`, `main.rs --preset` | Пользователь **вручную** выбирает профиль; умолчание в UI — **balanced**. |
| **Контекст данных и кодеки** | `src/analyzer.rs` — `DataContext`; `src/codec.rs` — `Codec::Store`, `best_compress` | Для блоков файла выбирается кодек; **Media → Store** без перекодирования потока; сравнение размеров в памяти. |

То есть **внутри .oz** уже есть защита от бессмысленного сжатия медиа на уровне **кодека блока** (SMART-02 частично). **Нет** единой **таблицы расширение → профиль пресета** (chunked/solid/recovery) и **нет** автоподстановки выбранного пресета в UI при смене источника.

## Пробелы относительно ТЗ

- **SMART-01:** нужна явная **таблица** (в коде или конфиге): расширение или категория → рекомендуемый **`Preset`** (или правило «смешанная папка → balanced»).
- **SMART-02:** для lossless (исходники, диски, текст) — зафиксировать **balanced** или **max** (без ultra по умолчанию, чтобы не раздувать время); для **уже сжатых** медиа/архивов — **fast** (минимум solid/chunk overhead) или оставить пользовательский balanced с пояснением, что блоки всё равно пойдут в Store при классификации Media. План должен **не ломать** контракт `.oz` и не вводить lossy.

## Риски

- Папка с **смешанными** типами: правило по большинству расширений или консервативно **balanced**.
- Пользователь меняет пресет вручную — нужен флаг «авто отключено» или отдельная опция «Авто».

## Вывод для плана

1. Модуль или функции **`suggested_preset_for_input(path)`** (+ тесты на 2–3 класса: текст/код, медиа, смешанное).
2. UI: пункт **«Авто (по типу файлов)»** в селекторе **или** автоподстановка при выборе источника с возможностью отключить.
3. Документ **`docs/SMART-PRESETS.md`** (или раздел в существующем doc) с таблицей эвристик.
4. CLI (опционально): `--preset auto` при согласовании с `Preset::from_str`.
